# GPU Scene 切换预加载与资源缓存（2026-10-13）

## 本轮范围与约束

用户已授权改代码，由用户自行实测。本轮不运行测试、启动/注入/刷新 Codex、改日常配置、操作 Wallpaper Engine 原件或打包替换 EXE。既有未提交改动保留。源码同步不等于验收通过。

实施顺序：

1. 增加只读原始资源的有界内存缓存，保留文件 containment、vendor SHA-256 和 Range 校验；不缓存带会话 capability 的生成页面，不放宽 HTTP `no-store`。
2. 使用现有 M1 `prepare/ready/commit/cancel` 保留当前场景和一个候选；预加载首帧就绪后暂停、静音，选中时复用同一 iframe，不重新创建 GPU 场景。
3. 工作台卡片悬停/键盘聚焦 400 ms 后，同时预加载工作台与 Codex 的候选；点击时并行准备两边，不再等工作台冷加载后才通知 Codex。只有工作台预览成功后才保存选择，失败候选不替换当前壁纸。
4. 顺序/随机轮播提前确定下一候选并预加载；真正切换沿用同一候选，策略/列表/选择变化使其失效。
5. 增加预加载就绪/命中耗时日志，人工回读并同步真源；不运行自动化或实机测试。

并发：预加载准备和实际 apply 共用每个目标的短任务队列，首帧等待留在 renderer；真实 apply 优先使过期预加载失效。全局只保留当前请求的候选，候选超时/失败/恢复/退出均释放。最多两个 Codex Scene 资源服务、每个目标最多两个 Scene iframe。预加载不得为了腾位置提前结束既有过场。

## 实现边界

- 原始资源缓存为进程内 LRU：总计 128 MiB、单文件 32 MiB、最多 128 条；并发读取共用一次读取，读取中按原 stat 的大小分配有界 Buffer，文件被替换/增长则不接纳结果。超大文件或预算不足仍走原 Range 流。重新扫描及退出清理缓存，不新增磁盘缓存。
- 工作台另外保留自身当前场景和一个隐藏候选。Codex 的多个已核验页面共享只读资源服务，但每个页面仍有自己的 GPU 场景；不共享工作台 GPU 上下文。没有“把全部壁纸都常驻显存”的池。
- 每个候选最多保留 120 秒。首帧后暂停/静音，不影响当前壁纸播放。真实点击/选择加载优先于后续悬停；预加载状态不会阻断工作台的轮播状态轮询。
- 采用候选前重查项目注册/策略、root、manifest、scene.pkg 与已读取资源的文件元信息，并刷新作者属性；素材变更、候选失败、过期或验证不可用时释放候选，改为正常冷加载。不允许用旧候选绕过文件访问/作者属性校验。
- 轮播提前固定下一 id，随机模式切换时沿用这次选择；工作台读取同一 `nextId` 预热自身候选。悬停候选优先于工作台下一张的后台预热；资源/过场繁忙时预热可以被跳过。Codex 忙时 500 ms 重试，最多 10 次，不等待首帧占用控制队列。
- hover 不连接新 CDP、安装脚本、切 CSP、刷新页面或重启 Codex；仅已有 GPU 初始化的已安装页面可预热。首次注入/首次 GPU 文档初始化仍是原流程。
- 新日志：`scene-preload-ready` 的“候选首帧已预加载”，以及切换时的“GPU 预加载命中（首帧已就绪）”/“GPU 复用预加载（仍等待首帧）”/“GPU 冷加载”。这些日志不是物理屏幕 FPS 或已测切换速度的证明。
